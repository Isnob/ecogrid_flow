# Как мы работаем

Правила для всех участников: как вести задачи, ветки, коммиты и PR. Устройство системы — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Задачи
* Каждая работа — задача в «Сфере» с ключом `ID24_EGF-NN`, одним исполнителем и понятным результатом (файл, скрипт, эндпоинт).
* В работе у человека одновременно не больше одной задачи.
* Статус в «Сфере» меняется в тот же день, когда меняется состояние работы. Если работа заблокирована (нет токена, упал внешний API), в задаче ставится **Blocker** и пишется причина.

## Ветки
* Основная ветка разработки — `develop`. `master` — только релизы.
* Ветка создается от свежего `develop`, одна ветка — одна задача:

| Тип работы | Шаблон | Пример |
| :--- | :--- | :--- |
| Код | `feature/ID24_EGF-NN-кратко` | `feature/ID24_EGF-22-create-db-tables` |
| Инфраструктура, CI, Docker | `infra/ID24_EGF-NN-кратко` | `infra/ID24_EGF-16-postgres-docker-compose` |
| Только документы | `docs/ID24_EGF-NN-кратко` | `docs/ID24_EGF-14-sources-tables` |

## Коммиты
Коротко и по делу, с префиксом типа: `feat:`, `fix:`, `docs:`, `test:`, `chore:`. Например: `feat: add ENTSO-E prices table and hourly view`.

## Pull Request
* PR — в `develop`, в описании ключ задачи и что изменилось.
* Минимум один approve. Кто ревьюит:

| Что меняется | Ревьюер |
| :--- | :--- |
| Код backend, ETL, инфраструктура | Александр |
| Схема БД (`infra/db/init.sql`), данные, модель PUE, аналитика | Богдан, Арина |
| Веб-портал | Богдан (требования), Александр (интеграция с API) |
| Тесты | Григорий |

* **Контракты** (схема БД, вход и выход ядра, REST API — см. [ARCHITECTURE, п. 3](docs/ARCHITECTURE.md#3-контракты-между-частями)) меняются только через PR, и ревьюит их обязательно **потребитель** контракта: схему БД — Александр, контракт ядра — Александр, API — Максим.
* Решение, которое затрагивает несколько частей системы, оформляется как ADR в `docs/adr/`.

## Definition of Done
Задача считается сделанной, когда:
1. Код или документ влит в `develop` через PR с approve и без конфликтов.
2. Код запускается без ошибок, тесты и линтеры проходят.
3. Если задача меняет API, схему БД или архитектуру — в том же PR обновлены документы в `docs/` (ERD, контракты, ARCHITECTURE).
4. Если задача затрагивает сервисы — изменение проверено в Docker Compose.
5. Задача в «Сфере» переведена в Done со ссылкой на PR.

## Документация
* Рабочие документы — в `docs/` (карта — в [ARCHITECTURE, п. 6](docs/ARCHITECTURE.md#6-карта-документации)). Каждый факт описан в одном месте, остальные документы на него ссылаются.
* `docs/archive/` — учебные материалы (семинары, ТКУ1). Их не обновляем и не используем как источник истины.

# ID24_EGF-29: тесты существующего ETL

Из корня репозитория, Python 3.11 или новее:

```bash
python -m pip install -r services/etl/tests/requirements.txt
pytest services/etl
```

Файл зависимостей тестов включает основные зависимости ETL, в том числе psycopg для тестов DQ после объединения веток.

Тесты выполняются без БД, токена ENTSO-E и доступа к интернету. Вызовы
`requests.get` подменены; случайный настоящий HTTP-запрос завершает тест ошибкой.
CI может использовать те же команды. Рабочие сборщики и схема БД не изменены.

## Фикстуры

- `fixtures/entsoe/`: семь XML, предоставленных Богданом в ветке задачи №28.
  Скопированы без изменения содержимого. Покрывают PT15M, PT60M,
  пропуски A03, два ряда DE-LU, сутки перехода времени и ответ «нет данных».
- `fixtures/open_meteo_forecast.json` и `open_meteo_historical.json`: реальные
  ответы для Хельсинки, сохранённые отдельно для прогноза и архива.
- `fixtures/sources.json`: исходный коммит и пути XML, адреса запросов JSON,
  время их получения и SHA-256. Токены в фикстурах отсутствуют.

Ошибка неверного токена моделируется искусственным XML прямо в тесте и явно
помечена как искусственная. Изменение порядка рядов DE-LU, контрольная цена
в дополнительном ряду и null в погоде создаются в памяти; исходные файлы не меняются.

Проверяется восстановление пропусков именно в реальном сжатом ряду A03.
Поведение повреждённого A01 и укороченных массивов погоды этим набором не подтверждается.

Несмотря на имя fi_pt15m_with_negative_prices.xml, минимум цен в нём — 1,5 EUR/MWh. Отрицательная цена проверяется отдельной искусственной подстановкой в памяти.

Повторная выгрузка XML: python services/etl/tests/fetch_entsoe_fixtures.py. Это отдельный ручной сетевой шаг с ENTSOE_API_TOKEN; pytest его не вызывает. Подробности — fixtures/entsoe/README.md. После обновления фикстур нужно также обновить их сведения и SHA-256 в fixtures/sources.json.

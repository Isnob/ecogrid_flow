Семинар 6. Тема: управление разработкой ПО. Проектное управление.

Цель: научиться выявлять, оценивать и контролировать проектные и технологические риски системы.

Что необходимо сделать

1. Собрать риски по категориям: требования, сроки, команда, технологии, интеграции, данные, безопасность, эксплуатация.
2. Для рисков данных рассмотреть изменение схемы данных, недоступность источника, рост объема, ошибки качества, дубли, потерю/задержку данных.
3. Оценить вероятность и влияние.
4. Рассчитать/назначить уровень приоритета.
5. Определить стратегии: избежать, снизить, принять, передать.
6. Назначить владельца риска.
7. Определить три триггера/индикатора раннего предупреждения.
8. Создать задачи по снижению топ-рисков.

Артефакты по итогам семинара:

| Артефакт | Что должно быть показано |
| :--- | :--- |
| Реестр рисков | Минимум 10 рисков. |
| Матрица рисков | Вероятность × влияние. |
| План реагирования на риски | Меры и владельцы. |
| Задачи по управлению рисками | Задачи по снижению критических рисков. |

Контроль:

1. Есть минимум 3 риска, специфичных для данных.
2. Меры реагирования конкретны и выполнимы.
3. Высокие риски связаны с задачами.

Что сдает команда: Реестр рисков + матрица + план реагирования.

! Текстовый отчет без проектного артефакта не засчитывается. Результат должен быть зафиксирован в «Сфере» и/или репозитории: задача, схема, код, тесты, данные, метрики, логи, MR или релиз.

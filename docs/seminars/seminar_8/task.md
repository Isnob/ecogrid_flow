Семинар 8. Тема: масштабирование управления разработкой ПО.

Цель: применить идеи масштабируемого Agile к гипотетическому крупному проекту и понять границы применимости.

Что необходимо сделать

1. Сравнить, какие проблемы решают SAFe, LeSS и Nexus.
2. Выбрать модель координации или аргументировать отказ от формального фреймворка.
3. Сформировать общий backlog/portfolio view для нескольких команд.
4. Построить план общего релиза с крупными features.
5. Выявить зависимости и критический путь интеграции.
6. Определить общие архитектурные/данные решения, которые нельзя принимать локально.
7. Сформировать перечень факторов успеха и рисков масштабирования.

Артефакты по итогам семинара:

| Артефакт | Что должно быть показано |
| :--- | :--- |
| Сравнение фреймворков | Краткая таблица «проблема → механизм → применимость». |
| Release Plan | Крупные features и зависимости. |
| Вывод | Почему выбран подход или почему формальный фреймворк не нужен. |

Контроль:

1. Вывод не сводится к пересказу терминов.
2. Модель привязана к своему проекту.
3. Есть общие правила данных/архитектуры между командами.

Что сдает команда: Сравнение SAFe/LeSS/Nexus + общий release plan + вывод.

! Текстовый отчет без проектного артефакта не засчитывается. Результат должен быть зафиксирован в «Сфере» и/или репозитории: задача, схема, код, тесты, данные, метрики, логи, MR или релиз.

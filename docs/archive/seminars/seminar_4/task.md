Семинар 4. Тема: FR/NFR, требования к данным и критерии приемки.Цель: сформировать проверяемую спецификацию требований, включая требования к данным и качеству данных.Что необходимо сделать

1. Взять результаты семинара 3.
2. Выбрать 5 – 7 ключевых пользовательских сценариев.
3. Сформировать функциональные требования с идентификаторами.
4. Сформировать NFR: производительность, надежность, доступность, безопасность, сопровождаемость.
5. Добавить data-requirements: объем, частота, формат, схема, срок хранения, полнота, точность, актуальность/свежесть, допустимые пропуски.
6. Описать User Stories или Use Cases.
7. Сформировать критерии приемки; минимум один сценарий Given/When/Then.
8. Приоритизировать требования.
9. Выделить архитектурно значимые требования.
10. Создать процесс изменения требований и связать требования с backlog.

Артефакты по итогам семинара:

- Требования v1.0 (FR/NFR/data requirements).
- Критерии приемки (проверяемые условия приемки).
- ASR (Architecture Significant Requirement - архитектурные требования, ограничивающие архитектуру).
- Change log (журнал изменений - правила и история изменений требований).

Контроль:
- Нет слов «быстро/много/качественно» без метрики.
- Data-requirements можно проверить тестом/контролем.
- Критерии приемки согласованы с функциями и данными.

Что сдает команда:
Требования v1.0 + Критерии приемки + Архитектурные требования + журнал изменений.!

Текстовый отчет без проектного артефакта не засчитывается. Результат должен быть зафиксирован в «Сфере» и/или репозитории: задача, схема, код, тесты, данные, метрики, логи, MR или релиз.

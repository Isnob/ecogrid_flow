Семинар 5. Тема: управление разработкой ПО. Проектное управление.

Цель: оформить проект как управляемый проект: цели, содержание, этапы, контрольные точки и ответственность.

Что необходимо сделать

1. Сформировать устав проекта: цель, ценность, ограничения, допущения, ключевые стейкхолдеры.
2. Определить содержание первого семестра и критерии Release 0.5.
3. Построить WBS[1] по крупным результатам.
4. Сформировать дорожную карту с контрольными точками.
5. Назначить владельцев результатов.
6. Оценить ресурсы и ключевые зависимости.
7. Согласовать формат статуса проекта и частоту контроля.

Артефакты по итогам семинара:

| Артефакт | Что должно быть показано |
| :--- | :--- |
| Устав проекта | Цели, ограничения, допущения, роли. |
| WBS | Декомпозиция по результатам. |
| Дорожная карта | Контрольные точки до Release 0.5. |
| Матрица ответственности | Кто отвечает за ключевые результаты. |

Контроль:

1. Устав не дублирует требования.
2. Дорожная карта содержит результаты, а не только даты.
3. WBS покрывает разработку, данные, тестирование и эксплуатацию.

Что сдает команда: Устав проекта v1.0 + WBS + дорожная карта + ответственность.

! Текстовый отчет без проектного артефакта не засчитывается. Результат должен быть зафиксирован в «Сфере» и/или репозитории: задача, схема, код, тесты, данные, метрики, логи, MR или релиз.

[1] Work Breakdown Structure — иерархическая структура работ или структура декомпозиции работ.

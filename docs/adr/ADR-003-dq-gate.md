# ADR-003. Восстановление коротких пропусков в DQ Gate

Статус: Предложено. Задача: ID24_EGF-28. Ревью: Богдан; контракт с API и ядром — Александр и Арина.

ETL проверяет цены (−500…4000 EUR/MWh), температуру (−50…50 °C) и влажность (0…100%). Плохие строки попадают в журнал etl_dq_log, корректные — в рабочие таблицы. Проверяется всё запрошенное окно, в том числе края и пустой ответ.

Внутренний пропуск общей длительностью не больше часа заполняется средним двух ближайших корректных исходных значений до и после разрыва. Всем пропущенным интервалам подставляется одно среднее. Восстановленные значения для дальнейшего заполнения не используются. Пропуск больше часа или без одной из границ остаётся пустым и записывается в журнал.

Пример: 10, [пропуск 15 минут], [пропуск 15 минут], 30 → 10, 20, 20, 30. Пять пропущенных интервалов по 15 минут остаются пустыми. Пропуск в начале или конце окна тоже остаётся пустым.

Для цен сетка строится по зоне и разрешению PT15M/PT60M, для погоды — по часам UTC. Перевод часов учитывается по UTC-границам рыночных суток. Если ответ цен целиком пустой, разрешение неизвестно: фиксируется отсутствие диапазона, интервалы не создаются.

В таблицах imputation_method = NULL означает исходную строку; boundary_mean означает восстановленную. Исходное значение при новой загрузке заменяет оценку, оценка не заменяет исходное. Историческая медиана за 21 день исключена из DQ и остаётся только для оценочного варианта API по ADR-001. Старые строки с median_21d и nearest_hour требуют отдельного пересчёта: переименовывать их в boundary_mean неверно.

Представление v_entsoe_prices_hourly возвращает только полные часы. is_estimated = TRUE, если хотя бы один интервал восстановлен. Предпочтение отдаётся полностью исходному ряду, затем PT60M. API передаёт восстановленную цену в ядро как оценочную. Если оценка участвует в окне рекомендации либо базовой стоимости, результат имеет is_fallback = TRUE. Контракт согласуют Александр и Арина; реализация API и ядра вне этой задачи.

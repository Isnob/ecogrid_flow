### 5. Сформулировать проблему, которую должен решать продукт
* **Проблема:** Ресурсоемкие серверные вычисления (ночные dbt/Spark пайплайны, пересчет витрин DWH, обучение и валидация ML/LLM-моделей) запускаются компаниями «вслепую» по жесткому расписанию (`cron`) в одних и тех же локациях.
* **Экономические и технические последствия проблемы:**
  1. *Волатильность биржи:* Спотовые цены на электроэнергию (Day-Ahead) в Европе колеблются от отрицательных значений днем (избыток солнца) до сотен евро за МВт⋅ч ночью (работа газомазутных станций).
  2. *Погодный фактор (PUE):* Энергоэффективность охлаждения ЦОД напрямую зависит от уличной температуры воздуха (Free Cooling vs Chiller).
  3. *Итог:* Бизнес систематически переплачивает за потребляемую электроэнергию (попадая на часы пиковых биржевых тарифов и дорогого охлаждения) и генерирует избыточный углеродный след. Ручной поиск дешевого времени и дешевой страны под десятки регулярных задач с разными SLA физически невозможен.

### 7. Определить 5–7 основных возможностей будущей системы (MVP)
1. **Автоматический сбор данных (ETL):** фоновый сбор Day-Ahead тарифов энергобирж и прогнозов погоды по целевым энергозонам.
2. **Модуль контроля качества данных (Data Quality):** валидация пропусков, аномалий и выбросов перед сохранением в БД.
3. **Моделирование динамического PUE:** расчет фактического коэффициента энергоэффективности охлаждения дата-центров по температуре уличного воздуха.
4. **Оптимизация временного окна:** алгоритм поиска непрерывного минимума затрат методом скользящего окна под заданный SLA-дедлайн.
5. **Географический арбитраж (Geo-Arbitrage):** сопоставление тарифов разных энергозон и рекомендация переноса задачи в более дешевый дата-центр.
6. **Интеграционный REST API (FastAPI):** защищенный программный интерфейс для оркестраторов (`/recommendations`, `/analytics`).
7. **Пользовательский Web-интерфейс (React):** интерактивный корпоративный портал с картой энергозон, графиками волатильности и симулятором задач.

### 8. Определить источник или источники данных

* **Внешние публичные источники:**
  1. **ENTSO-E Transparency Platform API:** официальный открытый REST/XML API европейской энергосети (спотовые цены Day-Ahead, структура и объемы генерации по источникам).
  2. **Open-Meteo Weather Forecast API:** открытый REST/JSON API метеопрогнозов (температура, влажность, скорость ветра) около площадок ЦОД.
  3. **Исторические архивы Open-Meteo & ENTSO-E (за 3–5 лет):** ретроспективные данные для первичного EDA и последующего обучения ML-модели.
* **Внутренние источники данных клиента:**
  4. **Справочник инфраструктуры (`client_infrastructure`):** площадки ЦОД, географические координаты, базовый PUE, энергопотребление серверов в кВт.
  5. **Входные параметры вычислительной задачи:** длительность (ч), SLA-дедлайн, допустимые регионы, профиль мощности (передаются через JSON-запрос).

### 9. Кратко описать: какие данные поступают, как они должны обрабатываться, где храниться и кому предоставляться

* **Какие данные поступают:**
  * Рыночные временные ряды: временная метка UTC, энергозона, цена в EUR/MWh, объемы генерации по типам (ветер, солнце, газ, уголь);
  * Метеорологические данные: почасовая температура воздуха (°C), скорость ветра, солнечная радиация;
  * Параметры задачи от клиента: длительность выполнения, крайний срок завершения (SLA deadline), список доступных ЦОД, энергопотребление узла.
* **Как обрабатываются:**
  1. *Ingestion & Validation:* сбор данных воркерами, очистка, проверка полноты 24-часовых интервалов, дедупликация и интерполяция пропусков;
  2. *PUE Modeling:* расчет динамической поправки на охлаждение серверов по кусочно-линейной функции уличной температуры;
  3. *Optimization & Geo-Arbitrage:* сканирование почасовых тарифов методом скользящего окна по всем доступным энергозонам, вычисление интегральной стоимости и экономии относительно базового сценария.
* **Где хранятся:**
  * В реляционной СУБД **PostgreSQL 16**, развернутой строго внутри закрытого **On-Premise VPC** компании-клиента (7 таблиц: партиционированные по временным интервалам `market_day_ahead_prices`, `market_generation_mix`, `weather_forecast`, `weather_historical`, справочник `client_infrastructure`, таблицы `task_parameters` и `task_history`).
* **Кому предоставляются:**
  * *Внутренним системам оркестрации (Airflow):* машиночитаемый JSON-ответ REST API со слотом старта и локацией `{recommended_start_time, target_datacenter, expected_cost}`;
  * *Инженерам и руководству (FinOps/ESG):* интерактивные графики, карта энергозон и отчеты фактической экономии в корпоративном React-портале.
